## 本次实现功能

### 1. 支付模块分层架构 (`lib/features/payment/`)

按照 `application` / `data` / `presentation` 三层结构搭建支付体系：

- **application/** — 用例编排层
  - `PaymentGateway`：支付网关抽象接口，定义 `pay()` 统一入口
  - `PaymentService`：支付服务，根据支付方式选择对应网关并执行支付
  - `PaymentServiceFactory`：工厂方法，按 `enableRealPayment` 配置决定走 Mock 还是真实网关
  - `PaymentSdkInitializer`：支付 SDK 初始化器，在 `bootstrap()` 阶段调用

- **data/** — 数据与实现层
  - `MockPaymentGateway`：Mock 支付网关，模拟 `2s` 延迟后按 `90%` 概率返回成功/失败
  - `AlipayGateway`：支付宝真实实现预留（依赖 `tobias`）
  - `WechatPayGateway`：微信支付真实实现预留（依赖 `fluwx`）
  - `PaymentRequest`、`AlipayPaymentPayload`、`WechatPaymentPayload`：支付参数模型

- **presentation/** — 展示层模型
  - `PaymentMethod`：支付方式枚举（`alipay` / `wechatPay`）
  - `PaymentResult`：支付结果模型（`success` / `failed` / `cancelled`，含 `paymentMethod`、`transactionId`、`message`）

**设计要点**：
- 策略模式：通过 `PaymentGateway` 接口实现 Mock/Real 双路径，本地联调阶段走 Mock，后续接入真实 SDK 无需改动上层代码
- 工厂模式：`PaymentServiceFactory.create()` 统一创建逻辑，封装了配置判断
- 依赖注入：`PaymentService` 通过构造函数注入 `AppConfigStore`，便于测试时替换

### 2. 多环境配置体系 (`lib/app/config/`)

- **`AppEnvironment`**：编译期环境枚举，通过 `--dart-define=APP_ENV=dev|staging|prod` 控制
- **`AppConfig`**：应用运行时配置数据类（`apiBaseUrl`、`enableRealPayment`、`appTitle`、`enableDebugLog` 等字段，含 `copyWith`）
- **`AppConfigLoader`**：从 `assets/config/{env}.json` 加载 JSON 配置，支持 `AssetBundle` 注入（便于测试）
- **`AppConfigStore`**：全局配置存储单例，通过 `initialize()` 设置配置，通过 `read()` 读取

**设计要点**：
- 配置与代码分离：API 地址、功能开关等不硬编码在代码中
- 环境隔离：dev/staging/prod 三套配置，切换环境只需编译参数
- 可测试性：`AppConfigLoader` 接受 `AssetBundle` 参数，测试时可注入 Mock bundle

### 3. 个人中心功能完善 (`lib/features/profile/`)

- **`ProfilePage`**：个人信息卡片 + 订单状态概览（4 个状态入口 + 各状态订单计数） + 最近订单卡片 + 地址管理入口 + 基础设置
- **`AddressManagementPage`**：地址列表展示，支持"设为默认地址"
- **数据模型**：
  - `UserProfileSummary`：个人信息摘要（昵称、手机号、头像 URL）
  - `UserAddress`：收货地址（姓名、电话、省市区、详细地址、是否默认，含 `copyWith` 和 `fullAddress` getter）
  - `ProfileSettings`：基础设置（消息通知、生物解锁、降价提醒，含 `copyWith`）

### 4. 订单确认页增加支付方式选择

## 涉及技术

| 技术点 | 具体应用 |
|--------|----------|
| **抽象类与接口** | `PaymentGateway` 抽象类定义 `pay()` 契约，多个网关实现 |
| **工厂模式** | `PaymentServiceFactory.create()` 根据配置返回不同实现 |
| **策略模式** | `PaymentGateway` 接口 + `MockPaymentGateway` / `AlipayGateway` / `WechatPayGateway` |
| **单例模式** | `AppConfigStore` 使用私有构造函数 + `_instance` 静态字段 |
| **依赖注入** | `AppConfigLoader` 接收 `AssetBundle`、`PaymentService` 接收 `AppConfigStore`，均通过构造函数注入 |
| **`--dart-define` 编译期参数** | `String.fromEnvironment('APP_ENV')` 读取环境标识 |
| **`rootBundle.loadString`** | 从 `assets/` 加载 JSON 配置文件 |
| **`FutureBuilder`** | `OrderRecordPage` 使用异步加载 Mock 数据 |
| **`RadioListTile`** | 支付方式单选控件 |
| **`SwitchListTile`** | 设置页开关控件 |
| **Widget 测试** | `testWidgets`、`pumpWidget`、`find.text`、`find.byType`、`ValueKey` 定位、`tester.tap` |
| **单元测试** | `setUp`/`tearDown`、Mock 依赖注入、`expect` 断言 |
| **枚举 + extension** | `PaymentMethod`、`OrderStatus`、`AppEnvironment` 均使用 `enum` + `extension` 扩展方法 |

| **`DateTime` 与时间戳** | 订单记录中使用 `DateTime.now().millisecondsSinceEpoch` 生成订单号 |

## 实现说明

1. **支付架构的分层价值**：在 Flutter 电商项目中引入 `application/data/presentation` 三层，目的是让 Mock 和真实实现可以无痛切换。本地联调阶段走 Mock，架构上已为真实 SDK 接入预留位置。
2. **`--dart-define` 的使用场景**：相比手动改代码切换环境，编译期参数更安全、不易被误提交。适合控制 `apiBaseUrl`、`enableDebugLog`、`enableRealPayment` 等开关。
3. **测试即文档**：测试文件不仅验证功能，也是了解"这个模块怎么用"的最佳入口。当前测试覆盖了模型、服务、页面三个层级。
4. **`tobias` 和 `fluwx` 预埋策略**：当前只声明依赖和预留网关实现，不实际调用。待推进到跨端原生能力阶段时，只需填充网关实现即可。
5. **全局状态集中管理的代价**：当前 `MainTabPage` 承载了所有状态，对小型项目足够清晰。但随着功能增多，建议下一阶段引入轻量状态管理方案（如 `ChangeNotifier` + `Provider`），避免 `MainTabPage` 持续膨胀。
