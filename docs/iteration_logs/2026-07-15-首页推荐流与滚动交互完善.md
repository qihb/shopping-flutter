# 2026-07-15 首页推荐流与滚动交互完善

## 本次目标

在“首页模块初版”已经具备轮播区、分类入口和推荐商品卡片的基础上，继续把首页推荐区做得更接近真实电商场景，重点补齐：

- 推荐商品的分页加载体验
- 推荐区标题吸顶效果
- 首页下拉刷新行为
- 对应的 Widget 测试覆盖

这一步的意义，是让首页不只停留在“能展示内容”，而是开始具备更完整的滚动交互节奏。

## 本次实现功能

### 1. 首页滚动容器升级为 `CustomScrollView` + `Sliver`

当前首页已经不再用普通的整页 `ListView` 串内容，而是改成：

- `CustomScrollView`
- `SliverToBoxAdapter`
- `SliverPersistentHeader`
- `SliverList`

这样做之后，首页顶部搜索区、横幅区、分类区和推荐区可以被更细粒度地组织在同一个滚动体系里。

这也是一个很重要的阶段，因为首页开始采用更贴近真实业务页面的滚动结构，而不只是“一个列表放所有内容”。

### 2. 推荐商品区已经支持 mock 分页加载

当前首页推荐商品不再只有首屏 2 条静态内容，而是已经通过 mock 服务模拟“按页请求”：

- 首次进入页面时自动请求第一页
- 滚动接近底部时继续加载下一页
- 已有内容保留，新增内容追加在列表尾部
- 没有更多数据时展示“已全部加载完成”提示

相关逻辑现在主要分布在：

- `lib/features/home/presentation/pages/home_page.dart`
- `lib/features/home/data/home_recommend_mock_service.dart`
- `lib/features/home/presentation/models/home_recommend_product.dart`

当前 mock 服务一共准备了 3 页推荐商品数据，已经能够比较直观地验证：

- 异步请求
- 列表追加渲染
- `hasMore` 控制继续加载

这比“把所有商品一次性写死在页面里”更接近真实商品流的加载方式，也为后续接真实接口留出了清晰位置。

### 3. 推荐区标题已经支持吸顶

首页里的“为你推荐”标题现在不是普通文本，而是通过 `SliverPersistentHeader` 做成了吸顶区块。

当前效果是：

- 页面往下滚动后，推荐区标题会固定在顶部
- 用户继续浏览商品时，始终知道当前所在区块

这类交互在电商首页、商品列表和筛选页里都很常见。通过一个清晰的小场景先实现“吸顶头部”，比直接进入复杂筛选条实现更可控。

### 4. 首页已经补齐下拉刷新体验

当前首页外层包裹了 `RefreshIndicator`，支持通过手势触发整页刷新。

下拉刷新时会同时做几件事：

- 清空当前推荐商品列表
- 把分页状态重置回第一页
- 重新请求首页推荐数据
- 通过更新 `ValueKey` 的方式重建轮播组件，让轮播区回到初始页

这里很有工程价值，因为它展示了一个真实页面里“多个区块一起刷新”的基本思路，而不是只刷新某一个局部文本。

### 5. 推荐区加载态已经区分“首次加载”和“加载更多”

当前首页没有把所有加载状态混在一起，而是拆成了三种更清晰的反馈：

- 首次进入页面时的整段加载占位
- 滚动到底部后的“正在加载更多”提示
- 分页结束后的“已经全部加载完成”提示

这体现了一个常见的工程思路：

同样是加载状态，不同阶段对用户的反馈方式可以不同，页面体验也会更自然。

### 6. 首页推荐流测试已经补齐关键交互

除了原来的应用级 widget 测试外，现在还新增了首页专项测试：

- 滚动到底部后会加载下一页 mock 商品
- “为你推荐”标题滚动后会保持吸顶
- 下拉刷新后推荐区会回到第一页，同时轮播图回到初始内容

对应测试文件：

- `test/features/home/presentation/pages/home_page_test.dart`

这说明当前项目已经不只是“把界面搭出来”，也开始为真实滚动交互补充自动化验证。

## 涉及技术

### 1. `ScrollController`

首页现在通过 `ScrollController` 监听滚动位置，并在接近底部时触发下一页加载。

技术要点：

- 它可以拿到当前滚动容器的位置状态
- 常用于“无限滚动”“滚动监听”“返回顶部”这类交互
- `extentAfter` 很适合表达“离底部还有多远”

### 2. `CustomScrollView` 与 `Sliver`

这次首页开始正式使用 `Sliver` 体系来组织滚动内容。

技术要点：

- `CustomScrollView` 适合组合多种不同类型的滚动区块
- `SliverToBoxAdapter` 可以把普通 widget 接入 sliver 体系
- `SliverList` 适合承载一组可滚动列表项
- `SliverPersistentHeader` 很适合实现吸顶标题或吸顶筛选条

### 3. `RefreshIndicator`

本次首页通过 `RefreshIndicator` 增加下拉刷新能力。

技术要点：

- 它通常包在可滚动组件外层
- 用户下拉到一定距离后，会触发一个返回 `Future` 的刷新方法
- 很适合组织“重新请求页面数据”的交互

### 4. `Future`、`async/await`

首页推荐区的 mock 请求是一个异步过程。

技术要点：

- `Future` 即“稍后才会拿到的结果”
- `async/await` 可以把异步写法写得更像同步流程
- 在 Flutter 页面里做异步请求时，要留意 `mounted`，避免页面销毁后继续更新状态

### 5. 本地状态拆分

当前首页把推荐区相关状态拆成了多个字段，例如：

- 是否首次加载
- 是否正在加载更多
- 是否仍有下一页
- 下一页页码

技术要点：

- 页面状态拆清楚后，交互逻辑会更容易读懂
- 这也是后续引入更正式状态管理方案前的重要基础

## 实现说明

这一阶段重点验证了两件事：

1. 页面滚动结构不只是“能滚动”，还要考虑区块如何组合、标题是否吸顶、数据如何按节奏进入页面。
2. 电商首页里的推荐流通常不是一次性渲染完成，而是伴随滚动、刷新、分页不断变化的。

对应到已有前端经验的映射：

- `CustomScrollView + Sliver` 类似“一个页面里混合多种滚动 section 的布局系统”
- `RefreshIndicator` 类似移动端列表的下拉刷新容器
- mock 分页服务类似前端开发时先用假接口把列表流转跑通
