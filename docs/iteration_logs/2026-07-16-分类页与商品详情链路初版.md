# 2026-07-16 分类页与商品详情链路初版

## 本次目标

在首页推荐流和分类快捷入口已经具备基础展示能力之后，继续把电商浏览路径往前推进一小步，重点补齐：

- 首页分类入口的点击承接
- 分类页的基础双栏结构
- 推荐商品进入商品详情页的跳转链路
- 对应页面与流程测试

这一阶段的意义，是让项目从“首页能看内容”继续前进到“用户可以继续逛下去”，先把最基础的浏览链路串起来。

## 本次实现功能

### 1. 首页热门分类已经可以切到分类页

当前首页里的“热门分类”不再只是静态入口，而是会把点击结果通过回调抛给外层主页面处理。

主页面里的承接逻辑现在是：

- 记录当前点击的分类名称
- 切换到底部导航里的“分类”Tab
- 把选中的分类名称传给分类页作为初始选中项

相关文件：

- `lib/features/home/presentation/pages/home_page.dart`
- `lib/app/presentation/pages/main_tab_page.dart`

这样做很适合学习 Flutter 里的一个常见思路：

页面内部只负责发出交互事件，真正的页面切换和状态承接由更外层的页面统一处理。

### 2. 分类页已经从占位页升级为双栏浏览结构

当前分类页已经改成电商里常见的“双栏分类页”：

- 左侧是一级分类导航
- 右侧是当前分类下的商品网格

页面内部目前使用本地状态维护当前选中的分类索引，并根据选中结果切换右侧内容区。

右侧内容区包含：

- 当前分类标题
- 当前分类说明文案
- 4 列商品网格

相关文件：

- `lib/features/category/presentation/pages/category_page.dart`

这一步很重要，因为它让“分类页”不再只是一个空白容器，而是真正开始具备电商浏览页的空间结构。

### 3. 分类页支持首页带入初始分类

分类页新增了 `initialCategoryLabel` 参数，用来承接“从首页点某个分类后，进入分类页时应该默认选中谁”。

当前实现里做了两层处理：

- 首次进入页面时，在 `initState()` 里根据分类名称找到对应索引
- 如果外层重新传入了新的分类名称，还会在 `didUpdateWidget()` 里同步更新选中状态

这说明当前分类页已经不只是“自己内部切换内容”，也开始具备接收外部状态的能力。

对学习 Flutter 来说，这一步很有价值，因为它能帮助理解：

- `Widget` 参数如何驱动页面初始展示
- `StatefulWidget` 在外部输入变化时如何同步状态

### 4. 首页推荐商品已经可以进入商品详情页

当前首页推荐商品卡片已经接入点击行为，用户点击商品后会通过 `Navigator.push` 进入商品详情页。

商品详情页目前先实现为一个适合当前学习阶段的初版结构，包含：

- 顶部商品展示区
- 商品标签、标题、价格和简介
- 商品说明区
- “加入购物车”和“立即购买”两个底部操作按钮

相关文件：

- `lib/features/home/presentation/pages/home_page.dart`
- `lib/features/home/presentation/pages/product_detail_page.dart`
- `lib/features/home/presentation/widgets/recommend_product_card.dart`

虽然这版详情页还是静态信息为主，但已经把“首页推荐列表 -> 商品详情页”的基本跳转跑通了。

## 当前涉及的 Flutter / Dart 知识点

### 1. `StatefulWidget` 与本地状态

分类页和主页面都使用了 `StatefulWidget`。

学习要点：

- 当页面里有“当前选中项”“当前 Tab”等会变化的数据时，通常需要本地状态
- `setState()` 的作用可以先理解成“告诉 Flutter 这块 UI 需要重新根据最新状态绘制”

### 2. 参数驱动页面展示

分类页通过 `initialCategoryLabel` 接收首页传入的分类名。

学习要点：

- Flutter 页面和组件也可以像前端组件一样通过参数控制初始展示结果
- 当外层传入的数据变化时，页面内部有时需要显式同步自己的状态

### 3. `initState()` 与 `didUpdateWidget()`

这次分类页同时用到了这两个生命周期方法。

学习要点：

- `initState()` 适合做“首次进入页面时”的初始化逻辑
- `didUpdateWidget()` 适合处理“外层参数发生变化后，页面内部要不要跟着更新”
- 这是学习 `StatefulWidget` 时一个很典型的真实场景

### 4. `Navigator.push`

首页进入详情页使用了 `Navigator.push`。

学习要点：

- 可以先把它理解成“把一个新页面压到当前页面上方”
- 这是 Flutter 里最基础的页面跳转方式之一
- 很适合先在小场景中理解页面栈的概念

### 5. `CustomScrollView`、`SliverGrid` 与 `Expanded`

分类页右侧内容区使用了 `CustomScrollView` 和 `SliverGrid`，整体双栏布局则借助 `Row` 与 `Expanded` 完成。

学习要点：

- `Expanded` 可以让右侧内容区占满横向剩余空间
- `SliverGrid` 适合做商品卡片这类规则网格列表
- 当页面里既有标题说明又有网格内容时，用 `CustomScrollView` 组织会更自然

## 学习备注

这一阶段很适合重点理解一件事：

电商页面不是孤立存在的，而是要逐步形成“入口 -> 列表/分类 -> 详情”的浏览路径。

如果你有前端经验，可以先这样类比：

- `MainTabPage` 有点像负责页面级路由承接的外层容器
- 首页把点击事件通过回调抛出去，类似子组件通知父级做页面切换
- `Navigator.push` 类似从当前页面继续进入下一层详情页
