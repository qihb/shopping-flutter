# 2026-07-17 订单与个人中心初版

## 本次目标

在“首页 -> 分类 -> 商品详情 -> 加入购物车”这条浏览链路已经跑通之后，继续往电商的交易闭环推进一小步，重点补齐：

- 购物车的数量修改、合计金额与提交订单入口
- 下单后生成订单记录，并在“我的”页面能看到最近订单与订单状态入口
- 订单记录页作为订单状态入口的承接页
- 对应的流程测试覆盖

这一阶段的意义，是让项目从“能逛”继续前进到“能下单并回到个人中心看结果”，形成一个更像真实电商的最小闭环。

## 本次实现功能

### 1. 购物车页升级为可交互的商品清单

购物车页现在支持两种明确状态：

- 空购物车：提示用户先去首页挑选商品
- 有商品：展示商品卡片列表、数量增减按钮、底部合计与“提交订单”按钮

关键实现点：

- 使用 `ListView.separated` 组织商品列表，天然适合“内容 + 分隔间距”的结构
- 用 `fold` 计算购物车合计金额，逻辑清晰且更贴合“累加”的语义
- 每个加减按钮用 `ValueKey` 标记，方便测试稳定定位

相关文件：

- `lib/features/cart/presentation/pages/cart_page.dart`
- `lib/features/cart/presentation/models/cart_item.dart`

### 2. 主页面统一承接购物车与订单状态（最小可用的“状态提升”）

当前项目仍处在学习阶段，没有引入状态管理库，因此采用更直观的方式：

- 在 `MainTabPage` 中维护：
  - 当前购物车条目列表 `_cartItems`
  - 订单记录列表 `_orders`
  - “我的”页设置项 `_settings`
- 通过回调把“加入购物车”“修改数量”“提交订单”“切换设置”等行为下发给各个 Tab 页面

这样做的好处是：每个页面只负责展示与发出事件，跨页面共享的数据由外层统一持有，符合 Flutter 入门阶段最典型的“自顶向下数据流”学习路径。

相关文件：

- `lib/app/presentation/pages/main_tab_page.dart`

### 3. 订单模型与提交订单逻辑初版

提交订单后会发生 3 件事：

1. 基于当前购物车条目生成一条 `OrderRecord`
2. 把订单插入到订单列表的最前面，模拟“最新订单”
3. 清空购物车，并切换到“我的”页展示订单结果

订单模型当前保持轻量化，主要目标是让 UI 有一份清晰的数据可以展示，后续再逐步补状态流转与真实接口。

相关文件：

- `lib/features/order/presentation/models/order_record.dart`
- `lib/app/presentation/pages/main_tab_page.dart`

### 4. “我的”页面初版：订单状态入口 + 最近订单 + 基础设置

“我的”页当前包含 3 个区块：

- 顶部个人信息摘要（头像、昵称、邮箱、会员等级、默认地址）
- 订单状态概览（待付款/待发货/待收货/已完成），并支持点击进入订单记录页
- 基础设置（消息通知 / 生物解锁 / 降价提醒），使用 `SwitchListTile` 实现最常见的设置交互

相关文件：

- `lib/features/profile/presentation/pages/profile_page.dart`
- `lib/features/profile/presentation/models/user_profile_summary.dart`
- `lib/features/profile/presentation/models/profile_settings.dart`

### 5. 新增订单记录页，承接“按状态查看订单”

订单记录页当前按传入的 `initialStatusLabel` 过滤订单列表，并提供：

- 顶部展示当前筛选条件
- 为空时给出明确的空态文案
- 有数据时展示订单卡片与商品清单

相关文件：

- `lib/features/order/presentation/pages/order_record_page.dart`

### 6. 补齐最小闭环测试：加入购物车、改数量、下单、订单入口与设置

这次测试覆盖重点从“浏览链路”扩展到了“交易链路”：

- 商品详情加入购物车后，购物车页能看到对应商品与合计金额
- 在购物车里修改数量后，数量文案与合计金额会同步更新
- 提交订单后，会生成订单并在“我的”页展示订单状态与最近订单
- 切换设置项后，设置区块的状态文案会更新
- 点击订单状态入口会跳转到订单记录页，并能正确显示筛选条件
- 从分类页进入详情并加入购物车，也能在购物车看到商品

## 当前涉及的 Flutter / Dart 知识点

### 1. “状态提升”与回调传递（不引库也能先跑起来）

当前选择把跨 Tab 的共享状态放在 `MainTabPage` 里，并用 `ValueChanged` / `VoidCallback` 往下传递事件处理函数。

学习要点：

- 子页面负责触发事件，父页面负责修改数据并 `setState()`
- 对 Flutter 初学者来说，这是一条非常典型、可解释性很强的状态学习路径

### 2. `ListView.separated`、`fold` 与“合计金额”

购物车页用 `fold` 做总价累加，语义接近“把数组 reduce 成一个结果”。

学习要点：

- `fold` 的好处是把“从 0 开始累加”的意图写得更显式
- 列表 UI 用 `ListView.separated` 能减少布局里的重复间距代码

### 3. `SwitchListTile` 与设置页的常见结构

“我的”页设置区块使用 `SwitchListTile` 快速搭出开关设置项，并通过外部回调修改状态。

学习要点：

- `SwitchListTile` 是“标题 + 描述 + Switch”一体的常用组件
- 当设置项需要被测试时，用 `ValueKey` 给每个条目稳定定位

### 4. `Navigator.push` + `MaterialPageRoute`：从入口进入“列表页”

点击订单状态后会 `push` 进入订单记录页。

学习要点：

- 可以先把这理解成“从个人中心进入一层更具体的列表页”
- 订单记录页通过参数接收筛选条件，是很常见的页面复用方式

## 学习备注

这一阶段非常适合重点理解“最小闭环”的构成：

- 浏览（首页/分类/详情）
- 加购（把商品转换成购物车条目）
- 下单（把购物车快照转换成订单记录）
- 回到个人中心查看结果（订单状态入口 + 最近订单）

如果你有前端经验，可以类比：

- `MainTabPage` 像一个最小的“页面级 store”，先不用状态管理库也能把数据统一起来
- 页面之间通过回调交换事件，类似子组件 emit/回调到父组件做状态更新
