# 2026-10-07 真实登录流程对接

## 本次目标

按照 `docs/api/接口清单.md`（spring-shop 用户端接口，服务地址 `http://localhost:6001`），把登录流程从无到有接入真实后端：账号密码登录、注册自动登录、退出登录、冷启动会话恢复，以及后续请求自动携带 JWT。

## 本次实现功能

1. **登录态全链路**：登录 → token 持久化 → 业务请求自动带 `Authorization: Bearer <token>` → 冷启动用 `/api/user/me` 校验恢复登录态 → 退出登录（本地清凭证 + 后端拉黑 token）。
2. **注册自动登录**：注册成功后自动调用登录接口，无需用户二次输入。
3. **“我的”页面接入登录态**：未登录显示访客卡片（点击进入登录页），登录后展示昵称/用户名、手机号，并在基础设置里出现“退出登录”入口。
4. **网络层升级**：`ApiClient` 支持 token 注入、单次附加请求头（登录接口的 `X-Client-Id`）、PUT/DELETE 方法；新增后端 `Result<T>` 统一响应解包。

## 当前涉及的 Flutter / Dart 技术点

- **HTTP Bearer 鉴权**：token 回调注入（`Future<String?> Function()?`），等价于 axios 拦截器读 store 的思路，保证每次请求拿到最新 token。
- **统一响应解包**：HTTP 层状态码在 `ApiClient` 处理，业务层 `code` 在 `parseResultData` 处理，两层职责不重叠。
- **`shared_preferences`**：Flutter 官方键值对存储插件，首次引入，用于 token 与设备 clientId 持久化。
- **级联操作符 `..`**：`AuthNotifier(...)..restoreSession()` 创建后立即触发异步会话恢复。
- **状态机思维**：`AuthStatus` 三态（restoring/unauthenticated/authenticated），会话恢复保证不会卡在中间态。
- **接口抽象 + 双实现**：`TokenStore` 抽象让测试可注入内存实现，避免依赖平台通道。
- **表单校验**：`Form` + `TextFormField.validator`，注册页校验规则与后端约束（4-20 / 6-32）对齐。

## 实现说明

- **clientId**：后端登录接口通过 `X-Client-Id` 识别设备。用“毫秒时间戳 + 随机数”生成 32 位十六进制串并在首次生成后持久化，避免为单个 id 引入 `uuid` 包。
- **错误提示**：后端业务错误（如“用户名或密码错误”）直接透传 message；网络异常用兜底文案。页面进入时调用 `clearError()` 清理上一次操作的旧错误。
- **退出登录兜底**：先本地清凭证，再尽力通知后端拉黑；后端失败不阻塞本地退出。
- **平台差异**：明文 HTTP 联调配置 iOS 走 ATS 例外、Android 走 `usesCleartextTraffic`，两处均已注释“上线 HTTPS 后移除”。
- **与现有 mock 链路的关系**：首页推荐仍走独立的 FakeStore `ApiClient`（自带 baseUrl），与登录用的 `ApiClient` 互不影响；后续商品/购物车模块接真实接口时，应复用 app.dart 里这个带 token 的客户端。
