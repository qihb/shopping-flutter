# 2026-10-07 网络层切换 dio

## 本次目标

按“用社区标准方案”的原则，把上一迭代自写的 `http` 薄封装网络层切换到社区事实标准 `dio`，为后续统一拦截器能力（token 注入、401 处理、重试、日志）打好基础。

## 选型说明

对比过 `dio_network_toolkit`（auth 刷新/重试/离线队列/缓存全家桶），但核实其 pub.dev 数据后放弃：

- 周下载量仅 ~59、6 likes、160 pub points，社区采用度极低
- publisher 为 unverified uploader，单人维护、1.0.4 早期版本，有供应链与弃坑风险
- 自带大量当前用不到的能力（离线队列、响应缓存、请求去重），属于过早抽象

最终选择 `dio` 本体（千万级周下载、社区标准），高采用度生态包（如 pretty_dio_logger、dio_smart_retry）按需再加。

## 本次实现功能

1. `ApiClient` 内部从 `http` 换成 `dio`，**对外接口保持不变**：`get/post/put/delete`、`tokenProvider`、`dispose()` 签名不动。
2. token 注入从 `tokenProvider` 直接调用改为 dio `InterceptorsWrapper.onRequest` 拦截器实现，语义等价，后续可继续追加拦截器。
3. dio 的 `DioException` 统一翻译为项目自定义 `ApiException`：有响应时带状态码与响应体，超时给专门文案，业务层无需感知 dio 类型。
4. 增加连接/接收 15s 超时默认值。
5. 测试侧用自写 `CapturingMockAdapter`（实现 dio `HttpClientAdapter`）替换 `http` 的 `MockClient`，新增 401 状态码翻译用例。
6. `http` 依赖移除，新增 `dio: ^5.7.0`。

## 关键修改文件

| 文件 | 改动 |

## 当前涉及的 Flutter / Dart 技术点

- **dio 分层**：`BaseOptions`（baseUrl/超时）→ `Interceptor`（横切逻辑）→ `HttpClientAdapter`（传输层，测试替换点）
- **异常翻译边界**：第三方异常类型只在 `ApiClient` 一个文件出现，对外统一为 `ApiException`
- **测试替换点差异**：`http` 替换 `Client`，dio 替换 `HttpClientAdapter`；JSON 请求体可能是 Map 也可能是已编码字符串，测试辅助函数做了归一化

## 实现说明

- Service 层（AuthService / HomeRecommendService）、`parseResultData`、所有页面与状态管理代码零改动，验证了当初“对内封 dio、对外留接口”的分层价值。
- `dio_web_adapter` 是 dio 在 Web 平台的传递依赖，自动引入，无需关心。
