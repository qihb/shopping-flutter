# 2026-06-20 首页模块初版

## 本次目标

在上一阶段“主框架与底部导航初版”的基础上，把首页从简单占位内容升级成更接近电商场景的可滚动首页草图，并补齐首页横幅、推荐商品、详情承接页和基础交互测试。

## 本次实现功能

### 1. 首页已经从占位页升级为电商首页草图

当前 `HomePage` 不再只是几段提示文案，而是已经具备一个更完整的首页结构，包含：

- 搜索入口占位条
- 轮播推荐区
- 热门分类快捷入口
- 推荐商品列表

页面仍然保持在 `lib/features/home/presentation/pages/home_page.dart` 内，便于当前阶段直接阅读，但已经开始体现“一个首页由多个 section 组成”的真实结构。

这一步很关键，因为它让首页不再只是“有页面”，而是开始具备电商首页最常见的区块编排方式。

### 2. 已接入可滚动的首页布局和区块拆分

首页内容现在通过 `ListView` 串联多个业务区块，这意味着：

- 首页内容超过一屏时可以自然滚动
- 各个区块之间通过 `SizedBox` 和统一间距组织
- 搜索区、标题区、分类区、推荐商品区已经拆成职责更清晰的小组件

当前首页内部已提取出这些局部组件：

- `_HomeSearchBar`
- `_HomeSectionTitle`
- `_HomeCategoryChip`

虽然这些组件仍然放在同一个文件里，但职责已经比“把所有 UI 全写进一个 `build()` 方法”清晰很多，适合当前阶段逐步演进。

### 3. 首页轮播区已经支持图片与视频两类素材

这次首页最核心的升级，是新增了轮播横幅组件：

- `lib/features/home/presentation/widgets/home_banner_carousel.dart`

当前轮播区已经完成：

- 使用 `PageView` 展示多张横幅内容
- 使用 `PageController` 控制轮播页切换
- 使用 `Timer.periodic` 实现自动轮播
- 底部指示器跟随当前页索引变化
- 同时支持图片素材和视频素材两种横幅类型

当前内置了 4 条假数据：

- 2 张图片素材
- 2 条视频素材

这比只做静态 Banner 更进一步，因为首页已经开始出现“内容位类型不同，展示方式也不同”的真实业务特征。

### 4. 横幅数据模型已经单独抽离

为了避免轮播组件里直接散落多组字段，这次新增了：

- `lib/features/home/presentation/models/home_banner_item.dart`

当前模型已经整理出：

- 标题
- 副标题
- 描述
- 标签
- 按钮文案
- 素材类型
- 主题色与背景色
- 图标
- 视频地址
- 时长文案

同时补了：

- `HomeBannerMediaType`
- `isVideo`
- `mediaTypeLabel`

这说明首页模块已经开始从“只写 UI”进入“UI + 轻量展示模型”的阶段，后续如果接接口数据，也有比较自然的迁移位置。

### 5. 横幅点击后已经有独立详情页承接

这次没有把横幅点击事件停留在“先不处理”，而是补了一个真实去向：

- `lib/features/home/presentation/pages/home_banner_detail_page.dart`

当前详情页已经具备：

- 顶部 `AppBar`

这一步的工程价值很高，因为它把“首页卡片 -> 点击进入详情”的页面流转链路先跑通了。后续无论承接活动页、专题页还是商品聚合页，都可以沿着这个位置继续扩展。

### 6. 已接入 `video_player`，并封装首页视频播放器

这次首页不只是用静态占位图模拟视频，而是已经引入：

- `video_player` 依赖

- `lib/features/home/presentation/widgets/home_banner_video_player.dart`

当前播放器组件已经覆盖：

- 控制器初始化

### 7. 横幅素材图也支持用纯 Flutter 方式生成

为了避免一开始就引入大量本地图片资源，这次还新增了：

- `lib/features/home/presentation/widgets/home_banner_media_artwork.dart`

它会根据素材类型，用渐变、图标、圆形装饰和块状占位结构直接生成横幅视觉内容。

这样做有两个好处：

- 先专注页面结构和组件拆分，不被资源管理打断
- 后续要换成真实图片或封面图时，只需要替换这个组件的展示实现

这是一种在实现上很务实的做法：先把结构和职责搭清楚，再逐步替换成真实数据和资源。

## 涉及技术

### 1. `ListView`

本次首页整体滚动容器使用了：

- `ListView`

技术要点：

- 它是 Flutter 中最常见的滚动列表组件之一
- 当页面内容超过一屏时，用它可以很自然地组织多个区块
- 在电商首页、商品列表、订单列表等场景里都非常常见

### 2. `Wrap`

本次热门分类快捷入口使用了：

- `Wrap`

技术要点：

- `Wrap` 会在一行放不下时自动换行
- 它很适合做数量不多、需要平铺排布的入口按钮
- 与前端的“自动换行 flex 布局”思路一致

### 3. `StatefulWidget` 与局部交互状态

这次首页模块再次深入使用了 `StatefulWidget`，主要体现在：

- `HomeBannerCarousel`
- `HomeBannerVideoPlayer`

技术要点：

- 当组件内部存在当前页索引、自动轮播计时器、播放器状态这类会变化的数据时，更适合用 `StatefulWidget`
- 这类状态不是全局状态，而是组件自身负责的一小块本地交互状态
- 它很适合用来表达“状态变化如何驱动 UI 更新”

### 4. `PageView` 与 `PageController`

首页轮播区已经使用：

- `PageView.builder`
- `PageController`

技术要点：

- `PageView` 适合做横向分页内容
- `PageController` 可以主动控制切页行为
- 电商首页 Banner、引导页、图片预览等场景都会经常用到

### 5. `Timer.periodic`

本次首页横幅自动播放使用了：

- `Timer.periodic`

技术要点：

- 它可以按固定时间间隔触发任务
- 在轮播图场景里，很适合驱动自动翻页
- 使用后要记得在 `dispose()` 中清理，避免资源泄漏

### 6. `Navigator.push` 与页面跳转

本次横幅点击后进入详情页使用了：

- `Navigator.of(context).push(...)`
- `MaterialPageRoute`

技术要点：

- 这是 Flutter 中最基础的页面跳转方式
- 即“把一个新页面压到栈顶”
- 在当前阶段先使用原生导航方式，后续再根据复杂度评估是否引入路由库

### 7. `video_player` 包

本次首次引入第三方依赖：

- `video_player`

它解决的问题：

- 让首页轮播和详情页能够直接承载真实视频内容

为什么现在引入它：

- 当前首页已经有“视频素材内容位”的明确业务场景
- 如果继续只用静态占位，会丢掉视频初始化、播放控制、异常兜底这些关键能力点

当前已覆盖的能力包括：

- `VideoPlayerController.networkUrl`
- `initialize()`
- `setLooping(true)`
- `VideoPlayer`
- 视频状态监听

### 8. `FutureBuilder`

视频播放器初始化过程使用了：

- `FutureBuilder<void>`

技术要点：

- 它适合承接异步任务不同阶段的 UI 展示
- 当前它负责区分“加载中”“初始化完成”“初始化失败”三种状态
- 这和前端里根据异步请求状态切换加载态、成功态、失败态的思路一致

### 9. `Slider`

视频控件区使用了：

- `Slider`

技术要点：

- `Slider` 是 Flutter 里常见的滑动选择组件
- 在视频场景中，可以自然承载“拖动进度条跳转播放位置”的交互
- 它也能清晰表达组件事件回调和数值更新之间的关系

### 10. 轻量展示模型与派生属性

本次 `HomeBannerItem` 中除了基础字段，还补了：

- `isVideo`
- `mediaTypeLabel`

技术要点：

- 这种写法可以把“从原始字段推导出来的判断或文案”收敛到模型里
- 页面层就不需要反复判断 `mediaType == ...`
- 这是一种很轻量、但很实用的代码整洁方式
