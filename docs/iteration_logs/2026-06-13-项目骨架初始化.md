## 涉及技术

### 1. `main()` 与应用启动流程

- `main()` 是 Dart 程序入口
- Flutter 项目一般会从 `main()` 进入，再调用 `runApp()`
- 当前项目把启动前准备单独拆到了 `bootstrap.dart`

工程价值：

- 明确 Flutter 启动链路
- 方便后续加入配置初始化、日志初始化、本地存储初始化等能力

### 2. `StatelessWidget`

当前 `MyApp` 和 `HomePage` 都基于 `StatelessWidget`。

技术要点：

- `StatelessWidget` 本身不持有可变状态
- 它更适合当前这种“先把页面骨架搭起来”的阶段
- 即“根据输入描述 UI 的组件”

### 3. `MaterialApp`

`MaterialApp` 是 Flutter Material 风格应用的基础外壳。

当前它承担的职责：

- 应用标题
- 主题入口
- 首页入口

后续通常还会在这里继续接入：

- 路由
- 国际化
- 全局导航
- 深色主题

### 4. `ThemeData` 与 `ColorScheme`

当前主题通过 `ColorScheme.fromSeed()` 生成。

技术要点：

- 主题可以集中管理，避免页面里到处硬编码颜色
- `ColorScheme` 是 Material 3 推荐的配色组织方式
- 后续如果要统一按钮、卡片、输入框风格，也通常从主题入手

### 5. 常见布局组件

当前首页已经覆盖多个基础布局组件：

- `Padding`：给内容加内边距
- `Center`：让子组件居中
- `ConstrainedBox`：限制子组件最大宽度
- `Column`：纵向排列多个子组件
- `SizedBox`：制造固定间距

工程价值：

- 这是一组非常基础且高频的页面布局能力
- 后续做商品卡片、列表、详情页时都会频繁用到

### 6. `BuildContext` 与主题读取

当前页面中已经使用：

- `Theme.of(context)`

技术要点：

- `BuildContext` 可理解为组件在 widget tree 中的位置上下文
- 通过它可以读取主题、导航、媒体尺寸等上层信息
- 它在 Flutter 里非常常见，后续会频繁遇到

### 7. Widget 测试基础

当前测试已使用：

- `testWidgets`
- `WidgetTester`
- `pumpWidget`
- `find.text`
- `expect`

工程价值：

- 这是 Flutter UI 自动化测试最基础的一套能力
- 后续可以继续覆盖按钮点击、列表渲染、表单输入和页面跳转
